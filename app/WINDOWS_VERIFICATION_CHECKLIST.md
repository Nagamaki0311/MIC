# Windows実機での動作確認チェックリスト

このリポジトリの開発・自動テストはLinuxコンテナ上で行われており、実際の
Windows環境・Discordクライアント・SoloCast実機・VB-Audio Virtual Cableを
用いた確認は行われていません(docs/decisions.md D-001参照)。

以下は、開発環境(Linux)で実行した自動テスト(`app/tests/`, 26件pass)と
ベンチマーク(`app/tests/bench_chain.py`)で検証済みのDSPロジックを前提に、
**ユーザーご自身のWindows実機で確認していただく必要がある項目**です。
上から順に確認し、チェックボックスに印を付けてください。


## 1. ビルド

- [ ] `app/build/build_windows.bat` をWindows実機で実行し、エラーなく
      `dist\SoloClarity.exe` が生成されること
- [ ] 生成された `SoloClarity.exe` をダブルクリックし、ウィンドウが起動すること
- [ ] `.exe` のファイルサイズが極端に大きくない(数百MB超になっていないか。
      pyrnnoise/av/matplotlib等が誤って同梱されていないかの目安)こと


## 2. デバイス認識・キャプチャ

- [ ] HyperX SoloCastをUSB接続した状態で、「マイク(入力)」一覧に
      SoloCastの名前が表示されること
- [ ] VB-Audio Virtual Cableをインストール後、「出力先(仮想マイク)」一覧に
      「CABLE Input」が表示されること
- [ ] マイクを選択して「処理ON/OFF」をONにした状態で、入力レベルメーターが
      発声に応じてリアルタイムに動くこと


## 3. 仮想マイク出力

- [ ] Windowsの「サウンド設定」→「録音デバイス」で「CABLE Output」を選び、
      SoloClarity経由で加工された音声のレベルが表示されること
- [ ] 出力レベルメーターの動きと、実際にCABLE Output側で聞こえる/測定できる
      レベルが対応していること


## 4. 実際のDiscordでの聞き取りやすさ

- [ ] Discordの「音声・ビデオ」設定で入力デバイスを「CABLE Output」に変更し、
      マイクテスト機能で自分の声が認識されること
- [ ] 実際に別アカウント/別端末とDiscord通話し、以下を主観評価する
  - [ ] 「小さくて低い声＋高品質バックグラウンドノイズ抑制＋弱いインパクト音抑制」
        プリセット(既定)で、無加工時と比べて聞き取りやすくなっているか
  - [ ] 低い声の方は「低い声」プリセットで明瞭度が改善するか
  - [ ] 小さい声の方は「小さい声」プリセットで音量・聞き取りやすさが改善するか
  - [ ] 「ノイズ除去」を強くした際、ファン音・空調音等の背景(バックグラウンド)
        ノイズが目立たなくなるか
  - [ ] 「ノイズ除去」を強くしても、小さい声が不自然に途切れない(誤ゲーティング
        されない)か
  - [ ] キーボード打鍵・マウスクリック音が、背景ノイズほど強く消えすぎず、
        自然な範囲で残っているか(D-012のバックグラウンド/インパクト分離の
        意図どおりか)
  - [ ] 静かな部屋で発話の合間(完全な無音)を置いた直後、話し始めの一瞬(0.1〜
        0.2秒程度)だけ背景ノイズの抑制が弱まって聞こえないか(Reviewerが
        コード上で発見した既知の設計上の限界。トランジェント検出器が
        無音からの立ち上がりを単発インパクト音と区別できず、短時間
        バックグラウンド抑制が弱くなる。声自体は欠落しないため実害は
        限定的と考えられるが、実機での主観評価が必要。詳細はD-013の
        Reviewer指摘参照)
  - [ ] (T-008/D-015) 以下16の話し方・状況で、声がプツプツ途切れる/瞬間的に
        消えることがないか主観評価する: 小さい低い声/普通の低い声/普通の声/
        大きい声/「あーーー」等の持続発声/「もしもし」等の短い発声の反復/
        小さい声での長めの発話(朗読)/語尾を伸ばす発声/小声→通常の音量変化/
        通常→小声の音量変化/無音から話し始める瞬間/話し終えて無音になる瞬間/
        PCファン等の背景ノイズ下での小さい声/エアコン等の背景ノイズ下での
        小さい声/キーボード打鍵音がある中での小さい声/環境音+打鍵音+小さい声が
        重なる状況(自動テストでは`test_chain.py`の
        `TestQuietLowVoicePresetRealWorldScenarios`16シナリオとして検証済みだが、
        合成音声信号による検証のため実声での確認が必須)
  - [ ] (T-008/D-015) 完全な無音(発話していない)状態で、ごくわずかな残留ノイズが
        常時聞こえないか確認する(ゲートを完全ミュートからフロア(-18dBFS)への
        ダッキングへ変更したことによる意図的なトレードオフ。聞き取れる場合、
        許容範囲かどうかを主観評価してほしい)
  - [ ] (T-008/D-015) 「小さくて低い声＋高品質バックグラウンドノイズ抑制＋弱い
        インパクト音抑制」プリセット(既定)で、以前のバージョンと比べて声が
        近く・自然に聞こえるようになっているか(background_wet_dry_mixを
        1.00→0.85へ引き下げ、EQ低域カットを緩和した効果の確認)
- [ ] Discord自体の「ノイズ抑制」「エコーキャンセレーション」等の音声処理設定は
      SoloClarityと二重にかかり、こもり・音切れの原因になり得るため、
      SoloClarity側で処理する場合はDiscord側の同種設定と併用しないことを推奨する
      (このLinux開発環境ではDiscordクライアント自体が無く実機検証不可のため、
      実際の相互作用の確認はユーザー側でお願いします)


## 5. テストボタン

- [ ] 「テスト再生」ボタンを押すと、数秒間の録音→加工音の再生が実際に行われること
- [ ] 再生された音が、実際にDiscordで聞こえる加工後の声と近い印象であること


## 6. 常駐時のCPU・メモリ実測

- [ ] タスクマネージャーで、SoloClarity常駐中のCPU使用率・メモリ使用量を
      数分間観察し、極端な増加(メモリリーク)がないこと
- [ ] 具体的な実測値(CPU%, メモリMB)をこのファイルに追記していただけると、
      今後の軽量化判断の参考になります


## 7. 遅延の実測

- [ ] 実際に発声してから、CABLE Output側 or Discord通話相手に聞こえるまでの
      体感遅延を確認する(手拍子等を鳴らし、録画して波形のずれを見るとより正確)
- [ ] 「はじめにお読みください.txt」の遅延に関する記載が実態と大きくずれて
      いないか確認する
- [ ] T-004(D-009)の対応で、マイク入力と仮想マイク出力を橋渡しする
      ジッタバッファ(最大4フレーム=40ms)を新たに挟んでいるため、旧バージョン
      (単一ストリーム構成)と比べて体感遅延が悪化していないか確認する
- [ ] (T-008/D-015) ジッタバッファのpriming(起動直後・アンダーラン直後に
      2フレーム=20ms分溜まるまで無音を出力する仕組みを新規追加)により、
      アプリ起動直後・一時的な音切れの直後に、以前のバージョンより体感遅延が
      増えていないか確認する(最大+20ms程度を想定)
- [ ] (T-008/D-015 Reviewer差し戻し対応) dry/wetパスの時間整列(RNNoiseの実測
      出力遅延2フレーム=20msにdry信号を合わせるバッファを新規追加)により、
      常時さらに+20ms程度の処理遅延が増えている(priming分と合わせ最大+40ms程度を
      想定)。継続的な会話で違和感のある遅延になっていないか確認する


## 8. 設定の保存・復元

- [ ] マイク/出力先デバイス、プリセット、詳細設定を変更した状態で一度
      アプリを終了し、再起動後に設定が復元されること
      (`%APPDATA%\SoloClarity\config.json` が作成されていることも確認)


## 9. アンインストール・後片付け

- [ ] SoloClarity.exeを削除するだけでアプリ自体は完全に削除できること
      (レジストリ変更等が行われていないこと)
- [ ] VB-Audio Virtual Cableは別途、公式のアンインストーラーで削除できること
      (SoloClarity側での対応は不要)


## 10. 高DPI環境での表示崩れ

SoloClarityは起動時にWindowsのDPI Awarenessを設定するようにしていますが
(`ctypes.windll.shcore.SetProcessDpiAwareness`、失敗しても起動は継続する実装。
docs/decisions.md D-005参照)、実際の高DPIディスプレイでの見え方はこのLinux
開発環境では検証できません。

- [ ] ディスプレイの拡大率が125%/150%(Windowsノートで一般的)の環境で、文字・
      ボタン・スライダーがぼやけたり、意図しないサイズ(極端に小さい/大きい)に
      なっていないこと
- [ ] 拡大率100%の環境と見比べて、ウィジェットの重なり・はみ出し等のレイアウト崩れが
      ないこと
- [ ] マルチディスプレイ環境(拡大率が異なる複数モニタ)で、ウィンドウを別モニタへ
      移動した際の表示も確認する
- [ ] 「詳細設定を開く」でパネルを開いた際、スライダーのバー(トラック)・
      左右の目安ラベルが横方向に見切れず全て表示されること(v1.2.0実機で
      報告された不具合。T-007でCanvas幅を内容の実測値から動的算出するよう
      修正済み。docs/decisions.md D-014参照)
- [ ] ウィンドウの端をドラッグして手動でリサイズできること(T-007で
      `resizable(True, True)`化)。広げた際にデバイス選択等の他フレームが
      不自然に間延びしないこと、詳細設定パネルを開いた状態で高さ方向に
      広げるとパネルの表示領域も追従して広がること
- [ ] アプリ起動直後(詳細設定パネルを一度も開いていない状態)で、ウィンドウが
      不必要に縦長になっていないこと(基本画面のみがコンパクトに収まること)


## 11. デバイスの抜き差し

- [ ] SoloClarity起動・ストリーム動作中にHyperX SoloCastのUSBケーブルを抜いても、
      アプリがクラッシュしないこと(エラー表示または無音のいずれかになることを確認)
- [ ] 再接続後、デバイス一覧を選び直す、またはアプリを再起動すると、SoloCastが
      再び選択・使用できる状態に戻ること
- [ ] VB-Audio Virtual CableをSoloClarity起動後に(再)インストールした場合の挙動
      (デバイス一覧に反映されるタイミング等)も確認する


## 12. Discordとの起動順序

- [ ] SoloClarityを先に起動し、後からDiscordを起動しても「CABLE Output」がマイクと
      して選択・認識できること
- [ ] Discordを先に起動した状態でSoloClarityを起動・終了しても、Discord側の音声設定
      (入力デバイス選択等)が壊れたり変わったりしないこと


## 13. スリープ・スタンバイからの復帰

- [ ] SoloClarity起動中にPCをスリープ/スタンバイさせ、復帰後にマイク入力・出力の
      レベルメーターが自動的に動作を再開すること
- [ ] 復帰後に動作が固まっている場合、アプリの再起動が必要かどうかを確認し、
      必要な場合はその旨をこのファイルに追記する


## 14. Windows起動直後の動作

- [ ] Windows起動直後(他のアプリを開く前、SoloCast/VB-Cableのドライバ初期化が
      完了しているとは限らないタイミング)にSoloClarityを起動しても、デバイス一覧
      取得・ストリーム開始が正常に行えること
- [ ] スタートアップ登録はしていない前提(SoloClarityはレジストリ変更を行わない設計。
      9節参照)のため、毎回手動起動でこの項目を確認する


## 15. 長期間の実運用

- [ ] 複数日・複数回のDiscord通話にわたって実際に使用し、聞き取りやすさ・安定性
      (フリーズ・音切れ・メモリ使用量の増加傾向等)に問題がないか確認する
- [ ] 問題が起きた場合、発生日時・実施していた操作・症状をこのファイルまたは
      Issueに記録する(このLinux開発環境で実施したソークテスト(`app/tests/soak_chain.py`)は
      合成信号によるDSPロジック単体の安定性確認であり、実際のWindows常駐環境・
      Discord通話・他アプリとの同時実行下での長期安定性を代替するものではない)
